# Nested Stacks

Grouping CDK resources into child CloudFormation stacks to stay within CloudFormation limits or organize large templates.

## Code

```python
from aws_cdk import NestedStack, Duration
import aws_cdk.aws_cloudwatch as cw

class MonitoringStack(NestedStack):
    def __init__(self, scope: Construct, id: str, *,
                 dashboard_name: str,
                 **kwargs):
        super().__init__(scope, id,
                         timeout=Duration.minutes(30),
                         **kwargs)
        cw.Dashboard(self, "Dashboard",
            dashboard_name=dashboard_name,
        )

# Usage in a parent stack
class AppStack(Stack):
    def __init__(self, scope: Construct, id: str, **kwargs):
        super().__init__(scope, id, **kwargs)
        monitoring = MonitoringStack(self, "MonitoringNested",
            dashboard_name="app-prod",
        )
```

Passing parameters and referencing nested stack outputs:

```python
from aws_cdk import NestedStack, CfnOutput, Fn

class ChildStack(NestedStack):
    def __init__(self, scope: Construct, id: str, **kwargs):
        super().__init__(scope, id, **kwargs)
        self.bucket = s3.Bucket(self, "Bucket")
        CfnOutput(self, "BucketName", value=self.bucket.bucket_name)

# In parent
child = ChildStack(self, "Child")
# Nested stack outputs are accessible as Fn::GetAtt expressions
bucket_name = Fn.get_att(child.nested_stack_resource.ref, "Outputs.BucketName")
```

## What's Happening

- **`NestedStack`** creates an `AWS::CloudFormation::Stack` resource — a nested stack is a child CloudFormation stack whose template is inlined into the parent template. It is not a separate CDK stack and cannot be deployed independently.
- **Use nested stacks when** you approach CloudFormation limits: 500 resources per stack, 450 KB template body, 200 outputs. Splitting resource groups into nested stacks keeps the parent under these caps because each nested stack has its own limits.
- **Parent-child references**: Outputs from nested stacks can be referenced in the parent via `Fn::GetAtt`. Unlike CDK multi-stack apps (which use `Fn::ImportValue`), nested stack outputs stay within the parent template — no cross-stack exports are created.
- **Not independently deployable**: Nested stacks deploy as a unit with the parent. You cannot update or deploy a nested stack in isolation. If you need independent lifecycle, use [[multiple-stacks]] instead.
- **Same account and region**: Unlike CDK stacks, nested stacks cannot target different accounts or regions. They inherit the parent stack's environment.
- **`timeout`**: Nested stack creation can time out. Set it based on the expected provisioning time of the resources inside. The default is 60 minutes.
- **Parameters**: Pass values to nested stacks via `NestedStackProps(parameters={...})`. The child stack declares parameters via `CfnParameter` if it receives values from the parent.
- **Policy files**: `NestedStackProps(notification_arns=[...])` lets you configure CloudFormation stack events for the nested stack separately from the parent.

### Nested Stacks vs Multiple Stacks

| CDK multi-stack app | Nested stacks |
|---|---|
| Independent CloudFormation stacks | Single parent stack with inlined sub-templates |
| Cross-stack via `Fn::ImportValue` / `Export` | References via `Fn::GetAtt` — no exports |
| Each stack deploys independently | Deployed as one unit |
| Stacks can be in different accounts/regions | Same account and region as parent |
| Preferred unless hitting CFN limits | Use only when necessary for limits or template organization |

### Key CDK Concepts

- `NestedStack` is an L2 construct that wraps the `AWS::CloudFormation::Stack` resource type. Its template is generated by CDK from the construct tree inside the nested stack.
- The nested stack's template is an **asset** — CDK uploads it to the bootstrap bucket and references it via S3 URL in the parent template.
- `nested_stack_resource.ref` returns the logical ID of the `AWS::CloudFormation::Stack` resource, which you use with `Fn.get_att` to access outputs.
