# IAM Policy Documents with Conditions, Resources, and Multiple Statements

Constructing IAM policy documents manually using `PolicyDocument` and `PolicyStatement`, including condition operators, ARN composition, the Effect enum, and principal abstractions.

## Code

```python
from aws_cdk import aws_iam as iam

# Single statement with a condition
policy = iam.PolicyDocument(statements=[
    iam.PolicyStatement(
        actions=["s3:GetObject"],
        resources=[bucket.arn_for_objects("*")],
        conditions={"StringEquals": {"s3:prefix": "public/"}},
    )
])

# Multiple statements in one document
iam.PolicyDocument(statements=[
    iam.PolicyStatement(
        effect=iam.Effect.ALLOW,
        actions=["s3:GetObject", "s3:ListBucket"],
        resources=[bucket.bucket_arn, bucket.arn_for_objects("*")],
    ),
    iam.PolicyStatement(
        effect=iam.Effect.DENY,
        actions=["s3:DeleteObject"],
        resources=[bucket.arn_for_objects("*")],
        conditions={"StringNotEquals": {"s3:prefix": "archived/"}},
    ),
])

# Import a raw JSON policy into CDK
iam.PolicyStatement.from_json({
    "Effect": "Allow",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::my-bucket/*",
})

# Principals are modeled as objects, not JSON keys
iam.ServicePrincipal("ec2.amazonaws.com")
iam.AccountPrincipal("123456789012")
iam.ArnPrincipal("arn:aws:iam::123456789012:user/Alice")
iam.AnyPrincipal()
iam.CompositePrincipal(
    iam.ServicePrincipal("ec2.amazonaws.com"),
    iam.AccountPrincipal("123456789012"),
)
```

## What's Happening

- **`PolicyStatement`** is the CDK model for a single IAM statement block. It serializes to the JSON `Effect`, `Action`, `Resource`, and `Condition` properties. CDK does not validate action names or resource ARNs — that is an AWS IAM enforcement-time concern.

- **`conditions`** is a raw dict — CDK does not define enum types for condition operators (`StringEquals`, `ArnLike`, `DateGreaterThan`, etc.). The dict is serialized verbatim into the CloudFormation `Condition` property. This means typos in operator names are only caught by IAM policy simulation or deploy-time validation.

- **`arn_for_objects("*")`** vs **`bucket_arn`**: `bucket.arn_for_objects(prefix)` returns an ARN like `arn:aws:s3:::bucket-name/prefix*`. `bucket.bucket_arn` returns the bare bucket ARN (`arn:aws:s3:::bucket-name`). Use `arn_for_objects("*")` to scope permissions to objects within a bucket and `bucket_arn` for bucket-level actions like `s3:ListBucket` or `s3:GetBucketLocation`.

- **`Effect.ALLOW` / `.DENY`** is a CDK enum that synthesizes to `"Allow"` / `"Deny"` in the IAM JSON. Statements default to `ALLOW` if omitted.

- **Principals** abstract the IAM principal JSON key. `ServicePrincipal("ec2.amazonaws.com")` produces `"Service": "ec2.amazonaws.com"`, `AccountPrincipal("123456789012")` produces `"AWS": "123456789012"`, and `ArnPrincipal(arn)` produces `"AWS": <arn>`. `AnyPrincipal()` produces `"AWS": "*"` — use only with an explicit `Deny` or a condition like `StringNotEquals: aws:SourceAccount` to avoid open access.

- **`PolicyDocument` vs inline vs managed**: `PolicyDocument` is a reusable construct that synthesizes to a CloudFormation `AWS::IAM::Policy` (inline policy embedded in a role/user/group) or a standalone `Policy` resource. Inline policies are part of the role resource and cannot exceed the 10 KB size limit per entity; managed policies (`iam.ManagedPolicy`) are separate resources that can be attached to multiple principals and have higher size limits. Use managed policies for permissions shared across roles, inline policies for role-specific permissions.

### Key CDK Concepts

- `PolicyStatement.from_json()` is an escape hatch — it parses a raw IAM policy JSON dict into a `PolicyStatement` object, which can then be added to a `PolicyDocument`. Useful when migrating existing policy JSON or when the policy is generated by an external tool.
- `CompositePrincipal` combines multiple principals with logical OR — the IAM `Principal` JSON block receives multiple entries (e.g., both `Service` and `AWS`), and the statement applies if any matches.
- CDK does not model `NotAction`, `NotResource`, or `NotPrincipal` as separate types — these map to the `not_actions`, `not_resources`, and `not_principals` parameters on `PolicyStatement`.
- Condition values that reference CloudFormation pseudo-parameters (e.g., `aws:SourceAccount`) are passed as strings — CDK does not resolve them; CloudFormation substitutes the values at deploy time.
